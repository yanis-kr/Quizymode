# Web security headers (#811)

The production SPA is served from S3 through CloudFront distribution `EH1DS9REH8KR5` (alias `www.quizymode.com`). Before #811 it sent no security headers. This page is the rollout for them. The policy is generated by `scripts/infra/web-security-headers.mjs` so the CSP hashes and API origin always match the checked-in `index.html` and `.env.production`.

## Status on production (Free CloudFront plan)

CloudFront rejects custom response headers policies on the Free pricing plan ("Free pricing plan can't have ... Custom response headers policy"). Production therefore runs the AWS managed `Managed-SecurityHeadersPolicy`: `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, `Strict-Transport-Security: max-age=31536000`, `X-XSS-Protection`. The `Permissions-Policy` and CSP headers below are not live. Owner decision for #811: keep the managed headers; the rest is tracked in #862 (a CloudFront viewer-response Function, a paid plan, or an enforced meta CSP). The generator and the rollout below apply as soon as one of those is approved.

## Policy

| Header | Value | Why |
| --- | --- | --- |
| `X-Content-Type-Options` | `nosniff` | No MIME sniffing of scripts or styles. |
| `X-Frame-Options` and CSP `frame-ancestors` | `DENY` / `'none'` | The app is never framed (decision for #811: no framing at all). |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Full path stays inside the site; other sites get the origin only. |
| `Strict-Transport-Security` | one year, no `includeSubdomains`, no preload | `auth.quizymode.com` is a separate service, so subdomains are left alone. |
| `Permissions-Policy` | `camera=(self)`, microphone, geolocation, payment, usb off | Photo capture (AC 6.6.53) needs the camera; nothing else is used. |
| `Content-Security-Policy` | see below | Defense in depth against injected script. |

CSP: `default-src 'self'`; scripts `'self'`, `'wasm-unsafe-eval'` (Tesseract) and the sha256 of each inline script in `index.html` (the theme first-paint script); styles `'self'` plus `'unsafe-inline'` (React style attributes); images `'self' data: blob:` and the API origin (pictures are served by the API, `Media__Delivery__Mode=Proxy`); `connect-src` the API origin, `https://cognito-idp.<region>.amazonaws.com` and the Cognito domain; workers `'self' blob:`; `object-src 'none'`; `base-uri` and `form-action` `'self'`.

## Rollout

1. **Report-only first.** Create the policy with the default mode (`report-only`). It sends the four always-on headers, `Permissions-Policy` and `Content-Security-Policy-Report-Only`. Nothing can break except by the always-on headers.
2. Browse the signed-out site and the signed-in site (sign in, study, quiz, add a picture, take a photo, OCR a PDF) with the browser console open. Any `[Report Only]` message is a directive to fix in `buildCsp`.
3. **Enforce.** Regenerate with `--mode enforce` and update the policy. Repeat the browse. If sign-in or the API breaks, roll back by regenerating in `report-only` mode (one command).

## Commands

```powershell
node scripts/infra/web-security-headers.mjs --out policy.json            # or --mode enforce
aws cloudfront create-response-headers-policy --response-headers-policy-config file://policy.json
# note the new policy Id, then attach it to the default cache behavior:
aws cloudfront get-distribution-config --id EH1DS9REH8KR5 > dist.json    # edit DefaultCacheBehavior.ResponseHeadersPolicyId, keep the ETag
aws cloudfront update-distribution --id EH1DS9REH8KR5 --if-match <ETag> --distribution-config file://dist-config.json
# later changes to the policy:
aws cloudfront update-response-headers-policy --id <policy id> --if-match <ETag> --response-headers-policy-config file://policy.json
```

## Check

```powershell
curl.exe -sI https://www.quizymode.com/ | Select-String -Pattern "x-content-type|x-frame|referrer-policy|strict-transport|permissions-policy|content-security"
```

Re-run the OCR and sign-in checks after every policy change. A new external origin in the app (analytics, fonts, a CDN) must be added to `buildCsp` in the same change.
